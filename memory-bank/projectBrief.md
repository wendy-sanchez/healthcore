# Project Brief

## Resumen del proyecto
Este repositorio implementa entregables progresivos para el escenario empresarial de HealthCore (red de clínicas ambulatorias en EE. UU. y Reino Unido) dentro del track AI Engineering de 4Geeks Academy.

El proyecto combina múltiples frentes:
- Hito Web y Fundamentos: sitio público bilingüe (EN/ES), formulario de consulta de pacientes y utilidades TypeScript para lógica operativa.
- Hito Next.js (Talent Pipeline Tracker): interfaz para gestionar candidaturas de RR. HH. conectada a API.
- Hito Backend (Directorio de Proveedores): API FastAPI + TinyDB + Pydantic y su interfaz en el backoffice, solicitada por Diane Foster y Claire Whitfield.
- Cola de Tareas Asíncronas (Redis + Celery): sistema de cola para desacoplar operaciones pesadas de la API, con reintentos automáticos, Dead Letter Queue en TinyDB, y monitoreo con Flower. Convierte `POST /api/incidents/analyze` a asíncrono (HTTP 202 Accepted).
- Modelo de Pronóstico de Ventas (Regresión con XGBoost): modelo de predicción de ingresos mensuales con split temporal 8 años/2 años, métricas honestas sobre el conjunto de prueba (MSE, PSI, Gini, K2) y banda de variabilidad calibrada con errores fuera de muestra. Auditoría completa con corrección de fuga de datos en rolling features, descomposición aditiva del target, justificación de features y evidencia visual comparativa.
- **Evaluación técnica del modelo de pronóstico (bias/varianza)**: diagnóstico formal de overfitting mediante validación cruzada temporal (TimeSeriesSplit, 5 folds) y curva de aprendizaje, con acción correctiva específica (3 pasos) y reporte técnico auto-generado con veredicto de staging.
- **Agente de Soporte LangGraph — Part 2: External Tools**: Extensión del agente LangGraph con herramientas que consultan datos operativos en tiempo real (gestor de incidentes + gestor de inventario). El agente decide automáticamente si necesita RAG, tool(s) o ambos mediante clasificación léxica (sin LLM). Timeout 5s, fallback verificable, solo GET, 30 tests, documentado en `agente-soporte-langgraph.md`.
- **Sistema de Memoria Persistente del Agente — Hito 8**: Sistema de memoria para el agente LangGraph que le permite recordar hechos operativos entre conversaciones (preferencias de personal, patrones de incidencias, configuraciones operativas) con control explícito del usuario, auditoría completa y protección PHI. Implementado con TinyDB (3 tablas), clasificador de intención basado en reglas léxicas (sin LLM), y 3 nodos LangGraph integrados en el grafo existente. 32 tests de memoria + 32 tests originales = 64 tests. 11/11 acceptance criteria.

## Descripcion del negocio
HealthCore opera 12 clínicas ambulatorias y busca digitalizar procesos críticos. El problema inicial abordado en este repo es la falta de presencia digital creíble y la captura no estructurada de consultas de pacientes, que impacta conversión, experiencia del paciente y carga operativa en recepción.

En paralelo, se trabaja en digitalización interna para People/HR con un tracker de pipeline de talento para reducir fricción en reclutamiento y seguimiento de candidatos.

## Objetivos del proyecto
1. Publicar una landing page profesional y bilingüe alineada al contexto de negocio.
2. Capturar consultas de pacientes con validaciones robustas para reducir errores y tiempo de triaje.
3. Implementar utilidades TypeScript puras para analítica operativa (claims, no-shows, CME, búsqueda y validación de datos).
4. Construir una UI Next.js para gestionar candidatos con listado, filtros, detalle, actualización de estado/etapa y gestión de notas.
5. Mantener estandares técnicos: tipado estricto, separación por responsabilidades y UX clara en estados de carga/error/éxito.
6. Centralizar el directorio de proveedores en una API con validación estricta y trazabilidad de cambios de tarifa para auditorías de cumplimiento.
7. Implementar una cola de tareas asíncronas (Redis + Celery) para desacoplar operaciones pesadas (análisis de CSV) de la API, con reintentos automáticos, Dead Letter Queue y monitoreo Flower.
8. Producir un pronóstico de ventas defendible ante Finanzas: split temporal estricto 8/2 sin fuga de datos, métricas de error explicables (MSE, PSI, Gini, K2 + MAPE) calculadas solo sobre el conjunto de prueba, y una visualización con rango de variabilidad en lugar de un único número optimista.
9. **Evaluar formalmente el modelo de pronóstico** con diagnóstico de sesgo/varianza (underfitting/overfitting) respaldado por validación cruzada temporal y curvas de aprendizaje, no por opinión. La acción correctiva debe ser específica y coherente con el diagnóstico.
10. **Implementar un sistema RAG (Retrieval-Augmented Generation)** que permita al equipo de HealthCore consultar en lenguaje natural las políticas documentadas de la clínica (seguros, citas, referencias, pacientes nuevos), respondiendo exclusivamente con información extraída de los documentos oficiales, sin alucinaciones del LLM.
11. **Implementar un agente de soporte LangGraph** que envuelva el pipeline RAG existente en un grafo de decisión trazable, con estado explícito, nodos de responsabilidad única, aristas condicionales, checkpointing y tracing persistido. El agente debe reutilizar (no reescribir) las funciones `retrieve()` y `generate_answer()` existentes, mantener los tests RAG intactos, y exponer un endpoint HTTP delgado sin lógica de negocio.
12. **Extender el agente con herramientas externas (Parte 2)**: añadir tools que consulten datos operativos en tiempo real (gestor de incidentes y gestor de inventario). El agente debe decidir autónomamente si necesita RAG, tool(s) o ambos, sin que el usuario lo especifique. Las tools deben ser solo GET, con timeout explícito (5s), ruta de fallback verificable, y deben seguir el mismo contrato tipado del grafo.
13. **Implementar un sistema de memoria persistente para el agente LangGraph** que permita al agente recordar hechos operativos entre conversaciones con control explícito del usuario. La memoria debe: (a) usar un almacenamiento separado de RAG (TinyDB, no Qdrant), (b) validar PHI antes de cualquier escritura o propuesta, (c) requerir una decisión explícita del usuario (nunca escribir sin confirmación), (d) tener un clasificador de intención que no asuma aprobación por silencio/ambigüedad, (e) mantener un máximo de una propuesta pendiente a la vez, (f) auditar cada decisión, y (g) consolidar/limpiar hechos viejos automáticamente.
14. **Implementar un sistema de chat en tiempo real (WebSocket) para el Compliance Assistant** que permita conversaciones bidireccionales con streaming token-by-token, interrupción de generación en curso, reconexión con historial completo, y ligadura session_id ↔ thread_id de LangGraph para rehidratación de checkpoint.
15. **Auditoría de seguridad IA contra NIST AI RMF 1.0 + NIST CSF 2.0**: Auditar todos los sistemas de IA contra las 6 funciones NIST (Govern, Identify, Protect, Detect, Respond, Recover), inventariar 7 componentes IA con responsables y riesgos, implementar rate limiting en login (10/IP/60s) y agente (30/user/min), verificar protección PHI en todos los componentes, documentar 4 casos de prompt injection con resultados esperados, mapear contra HIPAA y UK GDPR, y producir un plan de mejora priorizado de 11 ítems.

## Problema que resuelve
- Externo (pacientes): corrige una presencia digital insuficiente y permite intake estructurado de consultas.
- Interno (operaciones/HR): centraliza y agiliza gestión de información operativa y de reclutamiento.
- Cumplimiento: da visibilidad de qué proveedores tienen acuerdos BAA/DPA firmados y conserva el histórico de la relación contractual.
- Técnico: establece una base escalable de utilidades y componentes para siguientes hitos (backend, telemetria, RAG, agentes, workflows).
- Cola de tareas asíncronas: desacopla el análisis pesado de CSV de incidencias de la API principal, permitiendo que los endpoints respondan inmediatamente (202 Accepted) mientras un worker independiente procesa la tarea en segundo plano con reintentos automáticos y Dead Letter Queue.
- Telemetría: monitorizar el comportamiento de usuarios y sistema mediante un pipeline de análisis (pandas + Supabase) con 5 métricas operativas, dashboard en backoffice y autenticación JWT funcional.
- Reporting mensual: pipeline ETL (Prefect 3.8.8) y API independiente (puerto 8001) para KPIs de desempeño de suministros por clínica, con dashboard protegido por JWT en el backoffice y mapeo de nombres reales de clínica.
- Pronóstico de ventas: sustituye la proyección a ojo de ingresos por un modelo entrenado solo con el pasado, evaluado con un horizonte de 2 años que el modelo nunca vio, y con una banda de incertidumbre derivada de errores reales fuera de muestra (no de la varianza de entrenamiento).
- Evaluación técnica del modelo: responde las preguntas del ticket (1) ¿underfitting/overfitting? (2) ¿estabilidad a través de splits? (3) ¿acción correctiva? con evidencia cuantitativa, no opinión. El reporte generado sirve como artefacto de decisión para pasar o no a staging.
- RAG Knowledge Base: permite a coordinadores y personal de HealthCore obtener respuestas precisas sobre políticas de la clínica sin tener que buscar manualmente en documentos. Reduce el tiempo de consulta y estandariza las respuestas. Elimina el riesgo de información desactualizada o incorrecta al limitar las respuestas al corpus documentado.
- **MCP Server (Model Context Protocol)**: Servidor MCP que expone Incidencias (5 tools) e Inventario (5 tools) como herramientas MCP protegidas con OAuth 2.1 vía mcpauth modo Resource Server. Incluye rechazo explícito de escritura en inventario (RETO 2), integración con LangGraph mediante langchain-mcp-adapters, logging con auditoría de cliente, y verificación de scopes granulares (incidents.read/write, inventory.read/write). Autenticación activada por defecto con token dev para desarrollo. 9/9 acceptance criteria cumplidos.
- **Sistema de Memoria Persistente del Agente**: Permite al agente LangGraph aprender de la interacción sin acumular basura en su memoria para siempre. El sistema usa TinyDB (separado de RAG), valida PHI contra 8 patrones (HIPAA + UK GDPR) tanto antes de proponer al usuario como antes de escribir, requiere decisión explícita del usuario (nunca asume aprobación por silencio), tiene un clasificador de intención basado en reglas léxicas (sin LLM), mantiene máximo una propuesta pendiente, audita cada decisión con 8 tipos de evento, y consolida/expira hechos viejos automáticamente (threshold 50 facts, TTL 90 días). 11/11 acceptance criteria cumplidos.
- **WebSocket Chat en Tiempo Real — Compliance Assistant**: Chat bidireccional en tiempo real con streaming token-by-token del agente LangGraph de Compliance. Usa `ChatSessionManager` singleton con sesiones in-memory, `ChatSessionPubSub` por sesión (colas `asyncio.Queue`), y `agent_graph.astream_events(version="v2")` para streaming. JWT vía query param. Interrupción vía `asyncio.Task.cancel()`. Reconexión con historial completo via `session_snapshot`. `thread_id = session_id` para checkpoint LangGraph. 35 tests WebSocket, todos pasan. 6/7 acceptance criteria cumplidos.
